# Data feature React parity

Source baseline: native `tinystudio/ui/pages/{datasets,repositories,training,evaluations,metrics}.js`, owning routes in `tinystudio/api/routes/{data,training,serving,interp,artifacts}.py`, and service metadata contracts. Original source and unrelated quality work were not edited.

Implemented controls and contracts:

| Route | Controls and endpoint families |
| --- | --- |
| Datasets | Name search, create wizard, source-mode compatibility, JSON/JSONL direct R2 grant/PUT/from-object and multipart import, measured transport status/cancel/retry, three-step synthetic settings and summary, files/URLs, rules/examples/system prompt/creativity/curation, background synthetic task |
| Dataset | Server offset/bucket paging with exact bucket denominator, bucket cards/select, complete datapoint message/detail evidence, download, confirmed delete preserving snapshots, add datapoint, enrich count/temperature/instructions/avoid, autosplit percentage and synthetic validation policy, snapshots list/create/download/confirmed delete, editable label vocabulary/add/remove/save/auto-label |

Intentional honesty boundaries: dataset quality histograms are aggregate profiles and offer no fabricated record drilldown. Near-duplicate indices are profile ordering positions, not database row IDs; their evidence may be inspected but cannot fetch an exact datapoint through a nonexistent API. Loss steps state whether a saved checkpoint exists. Numeric missing scores are rendered as missing, never zero. Transfers do not claim import/index success.

Validation: `npm --prefix frontend test -- src/features/data/data.test.tsx` passed **13/13**. Tests exercise real React controls and installed shared BoardUI upload, direct R2 request ordering and external credentials boundary option, fallback multipart fields, synthetic URL + zero creativity, mode compatibility, queued quality completion/failure/truncation/cancellation, Strict Mode quality admission, job snapshot/reasoning, evaluation choices across source tabs, >1000-row server paging, score edge bins, and actual linked histogram -> row -> prediction detail.

Initial test failures were investigated: BoardUI's actual upload requires ResizeObserver absent from jsdom (local geometry stub added); the fixture's user and assistant were intentionally identical (query changed to accept both matching cells); wizard busy state lasts through a promise microtask (test now waits for the next enabled user step). Assertions were retained.

Full `npm --prefix frontend run typecheck` currently reports only missing integration modules `features/interpretability` and `features/workspace`, which are owned by the parent. No data feature type errors remain. `git diff --check -- frontend/src/features/data` passed. Browser/viewport/live backend acceptance and independent verifier review remain parent integration gates; these feature tests do not establish them.
